Findings (no code changes)
1. fn_800E30D4, random mixed 18 (course 23). Every flag is CONFIRMED:
   a. A loop that does nothing (GameRound.c:1152-1162). The inner COURSE_UNLOCKED scan only breaks. The outer loop only sets nCourse to the value it already has. It also passes the list index k as a course id, which the nAvail loop does not do. It is dead in effect.
   b. Divide by zero: Rand_Next(1) % nHoles when the picked course has no hole of the wanted par, and % nAvail when no course is unlocked. On the GC, divwu by 0 does not trap, so holes[] is read at an undefined index and gives a garbage hole number. It is only reachable if a course lacks a par 3, 4 or 5; check the course data before calling it an EA bug. Port: guard both.
   c. Courses whose disc check (fn_80110180) fails are marked used, but only for a re-pick that fails inside the while loop, not the first failing pick. That marking is what lets the "every course before any repeats" rule finish when a course is not on the disc. So it looks deliberate, but the loop only ends by chance. Port: mark every failing pick.
   d. Also: nAvail counts unlocked courses but picks list positions 0..nAvail-1, so it assumes the unlocked ones come first in lbl_80184D40. Par-5 slots are kept apart only from each other and can sit next to a par 3.
   e. Also: through fn_800E14E0, its closing fn_800E1434 runs before b137 is set, so nCurCourse keeps the last course it probed. The next fn_800E1434 (round start, fn_800DCBBC) repairs it. The FE path (fn_800849F8) sets b137 first.
2. fn_800E2F14: CONFIRMED dead. bDead is never set, so the first loop does nothing. fn_80057364(i) is a stand-in, and the existing matching note says the real body is unknown. Harmless.
3. fn_800E0AF0 writing 4 floats: NOT a bug. Both callers (fn_800DDFB4, GM_ShowPostShotAnimation) pass Player.vBall (f32[4]), &PinPos.x (x,y,z,w) and f32[4] out buffers. TYPE: the params could be Vec4.
4. fn_800E14E0 / b136: the premise is wrong. fn_800E0B38 clears b136 on every mode setup (GameRound.c:112). FE_MessageTable sets it (fn_800819FC "pick the saved custom round"; line 1450). While it is set, a plain course id changes only nCurCourse and keeps the custom hole list. That looks deliberate, and the comment now says so.
5. fn_800E3AD4 and fn_800E3ADC: CONFIRMED identical (u8 return 0). They are the defaults for two different slots (pfnGoToPlayoff, pfnGameFinished). Keep both for the match; a port could share one body.
6. fn_800E1BBC: the "all 18 holes selected" reading is right. Callers use it as a full-round gate for end-of-game money, awards and hole contests, not as "round over" (Earnings.c:932 pairs it with hole 17). bD4 means a playoff is running (each mode's GoToPlayoff sets it). bD5 is the same all-18 answer, saved just before fn_800E2BA4 cuts the selection to one playoff hole (GameModeMatch.c:255-263), so the answer survives the playoff.
