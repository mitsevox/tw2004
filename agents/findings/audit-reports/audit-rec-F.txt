Findings (no code changed; all five lane 2 flags are confirmed, and the functions match EA's code exactly)
1. fn_800884F0 (harmless): it passes string arg0's pointer as the first argument of fn_800FDE58. This file's local prototype says `char* szName`, but GameMode8.c defines it as `int nPlayer` and never reads it (it always uses player 0). Fix for the type pass: the prototype disagrees with the definition. A 64-bit port would truncate the pointer, which is harmless because the value is unused.
2. fn_80089324 (a real EA bug, now proven with the asm): the course-record branch copies the 20-byte RecordEntry to the stack and passes that address to "%s". nValue sits at offset 0 and szName at 4, so the printed "name" is made of the value's bytes. For any value below 2^24 it comes out as an empty string, and nLen is 0. Every course record's holder name shown through this command is blank. The port should pass .szName, as the recA branch and fn_8008886C do.
3. fn_80088CF0: in cases 103 and 104, fn_801025F4's result is thrown away (the asm overwrites r3 right after the call), so the call is dead. nMult is unset only when nTourCardLevel is outside 0..6 (save.h: 0..6), which only a corrupt save can give; an EA bug note already covers it. Lane 2's TYPE note on case 103 does not apply: aMult is s32. Cases 101 and 102 with an out-of-range value, and an unknown selector, leave the result untouched.
4. fn_800894E8: it bumps lbl_80281EDC (-1..10) and writes it to arg2, but both paths then overwrite arg2 and nothing else reads the counter. It looks like leftover debug code: dead but harmless.
5. fn_80089D68 (slot 167) does nothing. Its only call is to fn_8008AC48(current player, string), and that function has an empty body. Also minor: fn_800850E4 calls lbl_801D83B0[nCmd] without a NULL or range test, so command 0 or 119 (both NULL slots) would jump to address 0. Guard it in the port.
