Findings (no code changed; every function here is exact, so this is EA's behaviour)
1. Prize columns (confirmed, Lane 2 right). fn_8011BAD4 passes aPrize[k][0]*1000 as nTotal and aPrize[k][1]*1000 as n to fn_800D3478 (TW06 GM_Earnings_TournamentPayout). There, row 0 gets n, and the others share (nTotal - n) by their weights. So [0] = total purse and [1] = first prize. EA's labels agree: EventInfo shows fn_800EFF7C as "Purse:" (fn_8011D280, fn_8011D658) and fn_800F00F8 as "Earnings:" under "Winner:" (fn_8011D4DC). Out-of-unit claims that repeat the swap, for the field/type pass: pgatour.h aPrize comment "first prize and purse" (the order is reversed); PGATourSimulation fn_80117E98 locals nFirstPrize/nPurse (swapped); EventInfo fn_8011D4DC comment "the player's earnings" (it is the winner's share); FE_PGATourMessages fn_8010F440 comment and local "the winner's earnings"/szEarnings (it is the purse).
2. Green speed is not restored (confirmed). fn_800EE0A0 saves options.n18 in lbl_80281674 and sets the round's value (fn_80055C40 -> gGreenSpeedSetting). No code anywhere in src/ reads lbl_80281674, and fn_800EE02C restores only nC and nWind. After a tour round, the player's n18 option keeps the tour's last value. It looks like an EA omission: keep it for the match, flag it for the port.
3. The season counter can reach 10 (confirmed). fn_800EFAD0 clamps nSeason to 10 (and sets nEvent 0, not -1), and its only caller, fn_8010EEA8, ignores the return value. The save then keeps season 10, and aStartDate[10] is read one past the 10-entry table by GetEventOnOrAfter, fn_800EFD38 and GetEndDate. GetEventByDate guards 0..9. On the GameCube, [10] is the high half of the next Tournament's nName (normally 0: no events). For tournament 30 it reads past aTournament into gPgaData.aTourEvent. A little-endian port would read the low half of nName (nonzero) and get phantom start dates. Needs a bound in the port.
4. bQuick is unsupported (confirmed). fn_800EF130's flag selects sim flags 3 (fn_801178C8: 1 = the player is in the field, 2 = the player's round is simulated too), not a faster sim. Both callers (fn_800EEF88, fn_800EF9D0) pass 0, so that branch is dead in the game. Parameter name for the later naming pass (e.g. bSimPlayer).
