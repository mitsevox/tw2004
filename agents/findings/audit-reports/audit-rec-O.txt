Findings (no code changed):
1. The start-up frame-time cap: REFUTED as stated. It is true that fn_8006D8E8 only advances uLast outside game type 1. But the time comes from watch 1 (fn_800954A4(1)). Common init fn_8006C7A8 -> fn_800952D8 stops and zeroes all 5 watches, and only GO_vInitIG and unpausing start watch 1. So in start-up (and in the front end) every reading is 0 and the frame time is 0 each frame, not 4 frames. The missing uLast update has no effect there. Actual behaviour: the loop's fFrameTime is the round's clock (0 outside a round and while paused, before fn_800DAF98 adjusts it). The two fn_800954A4(0) calls in fn_8006D8E8 only read, and their results are thrown away (dead).
2. fn_8006CFC8 never destroys the start-up camera: CONFIRMED. It frees the render camera, viewport and frame buffer (fn_800137B0/fn_80076B18/fn_8006E214), but never calls CA_vDestroyCamera(lbl_80281E60), which fn_8006CEFC created. The other exits (fn_8006CB2C, fn_8006CDC4) do call it. It is harmless in practice: the lens comes from StaticMemory, and the next mode's common init (fn_8006C7A8 -> fn_8000989C) empties that heap, and start-up only runs once. Keep this in mind for a PC port that swaps StaticMemory for malloc.
3. fn_8006DC4C passes a camera as fn_80013808's colour: CONFIRMED as a type mismatch, but the behaviour looks intended. fn_80013808 is (f32* pColour, u32 uFlags) (GoRenderCtx_Gc.c). Its call receives *lbl_80280DF0, the current Camera. fn_80014194 copies the first 3 floats, which are Camera.a0, set to (0, 0, 0.5, 0) by fn_80013E48. So the view is covered with the camera's own colour, and a0 is probably the camera's clear colour. The 3rd argument (lbl_80280DF0) is ignored. gomainloop.c's local prototype (void* pCamera, int n, void** ppSlot) disagrees with the definition. TYPE pass: pass ((Camera*)*lbl_80280DF0)->a0 if it still matches, and name a0 in the header pass.
4. fn_800162A4 is declared with no arguments but called with one: CONFIRMED. streammanagerhole.c:471 defines it as an empty void(void). gomainloop.c:56 declares (int nField), and fn_8006C69C passes the frame parity. It is harmless on PPC (the argument is ignored), but the prototypes conflict: unify them in the TYPE pass. fn_8006DC40 takes the same argument and is empty too.
5. EA dead code in fn_8006D27C (both lanes): the fn_80017004(nView) and bare fn_80035574() results are discarded, and nState != GS_GREEN_MORPH is tested twice in a row. The unit also has five empty hook stubs (fn_8006DC40/44/48, fn_8006DCA0/A4) and six empty stubs that run before each hook walk (fn_8006E0A8..E0BC).
