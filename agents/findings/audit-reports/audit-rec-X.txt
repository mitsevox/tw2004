Findings (no code changes):
- 0x8007117C (row 5 part.p4, run for each mesh part from LLObj_Gc.c:67 via fn_80008248): it calls fn_80076E24, which sets the global TexAnim count and time to 0. So freeing any one row-5 part forgets every texture animation, including those of parts still loaded. Rows 6/10's close hooks (0x800715AC, 0x8007165C) do not do this. Harmless only if all such models are freed together.
- 0x80071994: shutdown walks rows 0..19 in start order, while the rest of fn_80071890 reverses fn_8007185C. This matters only if a later row's close needs an earlier row still up.
- 0x8000A4E0: confirmed. When m22 == 0, m20 == 0 and m00 != 0 (|B| = 90 deg, C forced to 0), A = -atan2(m00, m00), which is always +-45/135 deg. For this convention the math needs atan2(-m02, m00). The unit is Matching, so this is EA's bug (already tagged "as in the original"). The unset-fC case (m22 != 0, m01 == m11 == 0) cannot happen for an exact Rz*Rx*Ry matrix: it needs cos B = 0, which forces m22 = 0. It can only happen for non-rotation input (callers: ActAnimal_SetWorldMatrix, char fn_80019358).
- 0x8000AC5C vs 0x8000ABE8: ABE8 maps z=-near to -1 and z=-far to 0 (GX). AC5C maps far to 0 but near to -1/fNear, so with GX clipping (-w <= z <= 0) its real near plane sits at fFar/(1+fFar-fNear), about 1.0 whatever fNear is (0.9998 for 0.1/4096). It is used only for flat lenses (fn_80008378 != 0 in RC_vUpdateRenderCtxScreenMatricesAndInfo, times fn_8000AB80's 2/w, 2/h), and it is still a perspective divide (w = -z), not orthographic.
- lbl_80281E80 (the copy fn_800718E4 writes through lbl_802811F8) has no reader in src/ or build asm, so it is write-only.
