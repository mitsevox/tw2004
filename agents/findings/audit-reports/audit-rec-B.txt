Findings (no code changed; lane 2's flags confirmed in the source)
1. 'TCMS' leak: GameMode4_UnregisterStreamClients drops only 'TCM '. The 'TCMS' handler stays registered, and its text buffer (fn_800951A0 in LoadTCMSFromStream) is never freed. A second load leaks the old buffer and overwrites the pointer. LoadTCMS also never frees the stream object (LoadTCM does, through fn_8000E790).
2. UFont pools have no bounds checks: UFont_DrawString in mode 0 takes pQueueNext++ from a 50-record pool, and UFont_CopyString writes into a 500-byte pool. Queuing more than 50 strings, or more than 500 chars of text (NULs included), in one frame overruns the heap.
3. UFont_FindFreeSlot returns -1 when all 6 slots are used. uiLoadFile.c:152-154 passes that straight to UFont_LoadFont (apFonts[(u32)-1], one slot before the array) and stores -1 as the UIFont's slot.
4. docs/tw06-names.md: after this batch is applied, the 800768E0 row (CA_vUpdateInternalFieldOfViewData) should point at 800763BC.
5. Port/TYPE notes (L2): fn_80076A38's ps_res is an estimate (the C fallback is exact). ViewController calls CA_vSetLookAtSide's 4th argument pUp, but it is the side (x) axis. fn_800354B4 takes u8* for a CamLens. fn_80012CB4 has an unused 5th parameter. fn_80012C54 puts an s32 into the u8 uA8. The queue draws LIFO per font. UFont_PackColor does not clamp.
