3. Lane flag, 80127E44 vs 80127D84 tie order: CONFIRMED. Products sort by name ascending ignoring case, equal names put A first (-1). Accomplishments sort by name DEScending, case-sensitive (wide compare), equal names put B first (1). Neither ever returns 0. This is EA's code and does no harm; the fn_80127E44 comment "then by name" does not say which way (left as is).
4. Lane flag, 80128200 after the CRC reset: CONFIRMED EA bug candidate. Line 178 tests eError (always NONE there) instead of eCrcError. A pfnReset failure is ignored: Update runs anyway and its result replaces the reset's error. Harmless while Reset cannot fail. Could get an "EA bug:" note after 100%.

Lane flag, u1160 holds a level: CONFIRMED. fn_8012AA7C writes fn_80128FD4's level of the STORED totals (before this game's merge) into args.pProduct->u1160. fn_80128488/fn_80128528 set it to 1, fn_8012A050 copies it, the packer clamps it to 0..EASB_MAX_LEVEL. EASB.c fn_8012D9B4/fn_8012E1E0 use it as an offset (level +/- (u1160 - 5)). Field-name/type pass: something like "the Bio level when loaded".

Even there, op 2 writes the rebuilt totals only if HEAD was corrupt (step 18), and op 3 (step 19) never rewrites HEAD. Counts differ too: a rebuild counts the valid records, while HEAD's count is +1 per new game (fn_80129F98) and packed with minimum 1.
